## Schema generation (caveat 2 — workaround used)

The chicken-and-egg described in the brief occurred exactly as predicted:
`auth.ts` imports `./schema` before it exists. I applied the documented
workaround:

1. Created stub `convex/betterAuth/schema.ts` with `export default {};`.
2. Ran `npx auth generate --config ./convex/betterAuth/auth.ts --output ./convex/betterAuth/schema.ts`.
   The CLI prompted interactively to overwrite the stub; I piped `Y` via stdin.
3. The stub was replaced with the real generated schema (`user`, `session`,
   `account`, `verification`, `jwks`).

This is the workaround the brief explicitly authorizes, so it is not flagged
as a concern on its own — it is noted here only for reproducibility.

## Concerns / deviations from the brief

### 1. Committed `convex/_generated/api.d.ts` in addition to the brief's `git add` list (necessary deviation)

The brief's Step 9 stages exactly:
```
git add convex/betterAuth convex/convex.config.ts convex/auth.config.ts convex/http.ts
```

I added one extra file: `convex/_generated/api.d.ts`. Reason:

- `convex/betterAuth/auth.ts` imports `{ components } from "../_generated/api"`
  and reads `components.betterAuth`.
- This repo commits `convex/_generated/` (it is **not** in `.gitignore` —
  confirmed the existing `api.d.ts`, `api.js`, `dataModel.d.ts`, `server.*`
  are all tracked).
- Running `convex dev` regenerated `convex/_generated/api.d.ts` to add:
  ```diff
  +import type * as http from "../http.js";
  ...
  -export declare const components: {};
  +export declare const components: {
  +  betterAuth: import("../betterAuth/_generated/component.js").ComponentApi<"betterAuth">;
  +};
  ```
- If this regenerated file is **not** committed alongside the new source,
  any fresh checkout would fail `npm run typecheck` (`components.betterAuth`
  would not exist on the type) until someone manually ran `convex dev`.

To keep the commit self-consistent (the task explicitly requires
"`npm run typecheck` passes before committing" and the commit should not
break a clean checkout), I staged the regenerated `api.d.ts` in the same
commit. The commit message is unchanged from the brief.

### 2. Also committed `convex/betterAuth/_generated/*` (component codegen)

`convex dev` also emitted `convex/betterAuth/_generated/{api,component,dataModel,server}.ts`
(the component's own codegen output). These were swept in by the brief's
`git add convex/betterAuth` glob. They are required for
`import { components } from "../_generated/api"` in `auth.ts` to resolve at
runtime/typecheck. This is consistent with the repo's convention of
committing `_generated` and is not a behavior change — just calling it out
since 12 files appear in the commit (7 brief files + 4 component codegen +
1 regenerated `api.d.ts`).

### 3. Lint warnings in generated code

`npm run lint` reports 2 warnings (0 errors) for unused `eslint-disable`
directives inside `convex/betterAuth/_generated/dataModel.ts` and
`convex/betterAuth/_generated/server.ts`. These files are emitted by the
Convex component toolchain and are not appropriate to hand-edit. The
repo's lint script already ignores the app-level
`convex/_generated/**` but not `convex/betterAuth/_generated/**`. Not
blocking; the same pattern will likely recur for any future local
component. Could be addressed in a later task by extending the lint
ignore glob, but that is outside this task's scope.
